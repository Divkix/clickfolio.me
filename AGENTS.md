# AGENTS.md — clickfolio.me

clickfolio.me turns an uploaded PDF resume into a hosted portfolio at `/@handle`: anon upload → Clerk sign-in → claim → AI parse (Cloudflare Workflow) → publish. It runs as one Cloudflare Worker: [vinext](https://github.com/cloudflare/vinext) (Next App Router on Vite) + React 19, Postgres (PlanetScale) via Hyperdrive + Drizzle, R2, Workflows, one Durable Object, Clerk auth (`@clerk/react` + `@clerk/backend`, **not** `@clerk/nextjs`). Toolchain is Vite+ (`vp`): Oxlint + Oxfmt + Vitest behind one CLI. Product/self-hosting docs: [README.md](README.md). Issues: `gh` on `Divkix/clickfolio.me`.

When you change something this file describes, update it in the same commit.

## Conventions

- **API routes:** wrap in `withUserEffect` / `withAdminEffect` (`lib/auth/with-auth.ts`; the handler returns an Effect, and services beyond `appLayer` are provided inside it with `Effect.provide`); respond only via `createSuccessResponse` / `createErrorResponse` + `ERROR_CODES` from `lib/utils/security-headers.ts` (they attach `SECURITY_HEADERS`); bound JSON bodies with `validateRequestSize` + `readJsonWithLimit` (Effect routes: `oversizedBodyResponse` + `readJsonBody` from `lib/effect/json-body.ts`); validate with a Zod schema from `lib/schemas/`. Reference shape: `app/api/profile/role/route.ts` (`withUserEffect`).
- **Auth layers:** pages call `getServerSession()` (`lib/auth/session.ts`; `findSession(request?)` is its Effect form) and `redirect("/")` after the page's `runPage` returns; APIs use `withUserEffect` / `withAdminEffect`, which build `appLayer(env)` and run through `runRoute` (`lib/auth/middleware.ts` only holds `requireCronAuth`). An expired or invalid token is signed-out (401); an unreachable JWKS or a bad/missing `CLERK_SECRET_KEY` is `ClerkFailed` (503/504/500), never a sign-out. `withUserEffect` answers **404** when the JWT is valid but the user row is missing (webhook lag) — treat as auth failure. Admin checks re-read `isAdmin` from DB every request; `user.role` is career level, never an authz signal.
- **DB:** `getDb(env.HYPERDRIVE)` per invocation, never cached at module scope. Multi-write → `db.transaction`. Postgres `23505` → HTTP 409. Driver: node-postgres (`pg` >= 8.16.3). Raw SQL goes through Drizzle `execute`; results expose `rows` and `rowCount`.
- **Schema:** timestamps are `timestamptz` with `mode:"string"` (ISO strings in app); enum-like columns are `text` + TS union (no PG enums); JSON is `jsonb`, no manual `JSON.parse`.
- **Effect (server I/O):** every server call to something external (Postgres, Clerk, R2, email, queues, Durable Objects, Workflow bindings, `fetch` to third parties) is an Effect with a tagged error. Each dependency is a `Context.Service` with an owning `Layer`; code yields the service and edges build the layers per invocation (request, queue batch, Workflow step, cron tick, DO call). No `ManagedRuntime`, no module-scope client, pool or token (one exception: `lib/umami/client.ts` keeps a per-isolate cache of the validated Umami login token string, never a client or a failure, dropped on a 401, with the shared login on its own timer), no importing a service's `make*` constructor into runtime code (lint rule). Run Effects only at edges: the route helper, `runWorkflowStep` inside `step.do`, and the cron/queue/DO/page entry points; no `Effect.run*` mid-logic and no Promise wrappers around Effects. Framework control flow (`redirect()`, `notFound()`, vinext's dynamic-usage throw) is thrown after the Effect returns, never inside it. Every external call has an explicit `Effect.timeout` from `lib/effect/timeouts.ts` and passes the Effect `AbortSignal` to anything that accepts one (`fetch`); `pg` and bindings ignore signals, so a timeout only stops waiting: never retry a timed-out non-idempotent write (email, queue send, DO notify, R2 put, webhook POST; R2 deletes are idempotent, so only the R2 delete Workflow retries them). Retry is decided at the layer that owns it: Workflows retries steps (map `retryable` to `NonRetryableError` as `runWorkflowStep` does, no `Schedule` inside a step), the queue consumer chooses `message.retry()` vs ack, routes never retry and answer 503, email never retries. Best-effort work (email, alerts, DO push) recovers from a named tagged error and logs it; no empty `catch`, no `.catch(() => …)` without a log. Data crossing the boundary (webhook bodies, Clerk and Umami responses, queue messages, Workflow params, DO requests, cookies, jsonb read back) is validated with Zod and fails as a tagged `InvalidInput`/`*Invalid` error; Effect Schema is not used. Every tagged error carries an HTTP status + `ERROR_CODES` entry (routes), a `retryable` flag (workflows/queue) and a log level. DB stays Drizzle (no Effect SQL). Logs and spans go through `log` and `withSpan`, never `Effect.log*`/`Effect.withSpan` (those bypass redaction and Workers traces). Parse/AI failures live in `lib/parse/failures.ts`, serialized with `toParseErrorJson()`; stored and wire formats stay backward compatible.
- **No Effect in client-reachable code:** `'use client'` modules, `instrumentation-client.ts` and everything they import (today incl. `lib/resume/lifecycle.ts`, `lib/utils/log.ts`, `lib/utils/error-fields.ts`, `lib/schemas/*`) never value-import `effect`, a tagged error class, or a module that does; `import type` is fine. Split mixed code into an Effect-free module (pattern: `lib/parse/error-types.ts`). Enforced by the `client-effect-guard` plugin in `vite.config.ts`: `pnpm run build` fails and prints each importer chain.
- **Rate limits** (`lib/rate-limit/`) fail closed: a store outage is `RateLimitUnavailable` (503 + `Retry-After`), never allowed. IP limits meter with an advisory-locked count+insert in one `Db.transaction`; `getClientIP` validates headers with Zod and anything invalid shares the `unknown` bucket. A Promise-bodied transaction cannot run `enforceRateLimitEffect`: count with `readQuotaIn(tx, …)` under the lock it holds, then `requireQuota(quota)` after it (claim intake).
- **Resume state:** status transitions, retry eligibility and status presentation belong to `lib/resume/lifecycle.ts` — call it rather than re-deriving. Workflow steps use status-guarded `UPDATE … RETURNING` and SQL-side increments so replays are safe. The `*/15 * * * *` sweep (`lib/cron/stranded-resumes.ts`) fails `pending_claim`/`queued` rows older than 15 min and `processing` rows older than 90 min (age = `COALESCE(queued_at, created_at)`, compared in SQL; limits and messages are in `lifecycle.ts`): `failed` with no `last_attempt_error`, so they stay manually retryable; it pushes a status notice, logs one `resume_swept` event per row and never emails. A run carries the row's `retryCount` in its Workflow params, and the claim, attempt-count, failure-record and terminal-failure updates in `lib/parse/pipeline.ts` (`ownsRow`) only touch the row while it still matches, so a run that outlived a sweep and a manual retry can neither double-parse nor fail the retried row (runs without the field skip the check). The sweep keeps `last_attempt_error` and `total_attempts`, so the existing retry caps (2 manual retries, 6 attempts, permanent error types) still apply. A new cron needs its expression in `wrangler.jsonc` `triggers.crons` and a `case` in `scheduled()`; an unlisted expression only logs `unknown cron trigger`.
- **Email:** Cloudflare `EMAIL` (`send_email`) sends permanent parse-failure/cache-expiry notifications in a separate journaled workflow step after DB work, with no automatic email retries. Use verified Clerk account email, never resume contact email. Sending failures must not block status updates. `EMAIL_FROM` and binding `allowed_sender_addresses` must match an onboarded domain; local sends are simulated unless `remote: true` is enabled. Provider acceptance followed by a crash before journaling can still duplicate an email. A timed-out send is logged with `outcome_unknown` and never retried.
- **Logging** in worker/workflows/cron: `log(level, msg, fields)` from `lib/utils/log.ts` (JSON lines, each tagged with `service.version`, `deployment.environment` and the `CF_VERSION_METADATA` version id). Caught errors go in as `...errorFields(error)` (`lib/utils/error-fields.ts`: message, name, SQLSTATE, stack; strips Drizzle's SQL params, redacts emails), never `String(error)`, client components included (browser console lines reach HyperDX). No handles, names, emails or R2 keys (they end in the uploaded file name) in log fields or error messages. Background work (cron, Workflow, DO) logs what it catches; rethrow where the platform should record or retry the failure.
- **Business metrics:** one `logEvent(event, fields, level?)` per outcome (`BusinessEvent` in `lib/utils/log.ts`), ids and enums named like the surrounding logs (`resumeId`, `errorType`), numeric metrics in snake_case with their unit (`duration_ms`, `size_bytes`, token counts). Failure events keep `error` or `warn` level; dashboards filter on `event`.
- **Server spans:** wrap external calls and DB-like work in `withSpan` (`lib/telemetry/spans.ts`); every Postgres statement already gets one via `traceQueries` in `getDb`. Span names and attributes stay low-cardinality and PII-free: enums, counts, model ids, opaque DB ids. Errors are recorded through `errorFields`. The runtime exposes no trace or span ids to code.
- **Browser telemetry:** funnel events go through `trackEvent` (`lib/telemetry/browser.ts`), typed in `ProductEvents` with enums and numbers only (no handles, file names, message text). Keep that module free of runtime imports beyond types: it loads in the entry chunk via `instrumentation-client.ts`. `__APP_VERSION__`/`__DEPLOY_ENV__` come from `define` in `vite.config.ts` (Workers Builds env).
- **Type assertions** need a `// SAFETY:` comment on the line above (lint rule `require-safety-comment-for-type-assertion`); the 18 `anti-slop/*` rules and 5 `anti-slop-effect/*` rules in `vite.config.ts` all run at error — read the rule file in `tools/oxlint/anti-slop/rules/` (or `effect/rules/`) when one fires. The Effect rules apply repo-wide: server code uses `catchTag`/`Match`; client-reachable code satisfies them with plain code (a `switch`/`if` chain on a local string union or wire JSON field), never by importing `Match` or a tagged error class.
- **Images:** plain `<img>`, not `next/image`.
- **Tests:** import from `vite-plus/test`, not `vitest`. Tests that depend on real SQL semantics (jsonb operators, window functions, upserts) use `createTestDb()` from `tests/helpers/pglite-db.ts` (in-process PGlite with `migrations_pg/` applied) instead of a mocked query chain; DB helpers under test take `PgQueryable` (`lib/db`) so both drivers fit. Pattern: hoisted `vi.mock(...)` at top, then `const { POST } = await import("@/app/api/…/route")` inside the test. Keep mocks typed, following the existing integration/security suites, without `as unknown as`. Route tests that sign a user in mock `authenticate` from `@/lib/auth/clerk` with `authenticateStub` (admin routes: `authenticateAdmin` from `@/lib/auth/admin` with `authenticateAdminStub`), both in `tests/helpers/authenticate-stub.ts`. Projects `integration` and `security` use the Node environment in `vite.config.ts`; select with `--project name`.
- **Commits:** Conventional Commits `type(scope): summary` (see `git log`).

## Gotchas

- **Dev server fails** with "no local hyperdrive connection string" unless `CLOUDFLARE_HYPERDRIVE_LOCAL_CONNECTION_STRING_HYPERDRIVE` is exported in the shell (a line in `.dev.vars` alone is not read for this). Other local secrets: copy `.env.example` → `.dev.vars`.
- **`drizzle-kit` needs `DATABASE_URL`** (direct PlanetScale URL); the Worker never uses it. `db:push` skips migration files — prototyping only.
- **Cascade footgun:** deleting a `users` row cascade-deletes their `site_data` (the live portfolio). Deleting a `resumes` row only sets `site_data.resume_id` to NULL (migrations 0005/0006), so the live site survives.
- **Account deletion** (`app/api/account/delete`): Clerk identity first (`Clerk.deleteUser`, a 404 counts as deleted), then one transaction that reads the resume R2 keys and deletes the `users` row, then the prefix sweep. A local failure after Clerk is a 500, not a success: the sign-in is gone so a retry cannot reach the route, and the `user.deleted` webhook finishes the cleanup. Warnings give counts, never R2 keys. The webhook deletes the row it mapped (Clerk id or external id), and a missing or malformed `CLERK_WEBHOOK_SECRET` is a 500 so Svix retries, never a 401.
- **Dual-write:** `user.showInDirectory` must stay in sync with `privacySettings.show_in_directory` (wizard + privacy routes both write). `/explore` reads the column, the sitemap reads `hide_from_search` in the jsonb.
- **`proxy.ts` only checks `__session` cookie presence** (forgeable; `__client` exists even when signed out). Real auth is in pages/APIs.
- **Resume text is stored raw**; React escapes on render. Never HTML-escape before storage (`migrations_pg/0009` had to undo that).
- **Generated files:** `lib/cloudflare-env.d.ts` (`cf-typegen`), `migrations_pg/*`, `lib/seo/lastmod.json` (pre-commit stamps it; `SKIP_LASTMOD=1` for non-content commits).
- **`/llms.txt` and `/llms-full.txt` are route handlers** built from `BLOG_POSTS`, `THEME_METADATA` etc. — a file in `public/` would shadow them.
- **Adding a theme:** follow the chain `THEME_IDS` → `THEME_METADATA` → `themeToShareVariant` + the five maps in `share-variants.ts` (a dark theme also needs a `case` in `getLinkedInIconVariant`, `lib/utils/share-actions.ts`, or its LinkedIn share icon is black on dark) → `TEMPLATE_LOADERS`/`DYNAMIC_TEMPLATES` → demo data → theme maps in `CreateYoursCTA`/`AttributionWidget` → landing-page copy in `lib/templates/theme-pages.ts` (`/templates/<kebab>`; optional `title` for a profession keyword) → `lib/seo/lastmod.json` → `public/previews/<kebab>.webp` (shot at 1280×800@2x from `/preview/<id>` after Google Fonts load, encoded with `sharp` webp q82). `Record<ThemeId,…>` types catch incomplete theme maps. Recommend it for roles via `PROFESSIONS[].themes`. `tests/integration/templates-render.test.ts` renders every theme in `THEME_IDS` against full, minimal, empty-string and oversized resumes, so a new theme is covered automatically; never write the template count into copy, use `TEMPLATE_COUNT`.
- **Removing a theme:** undo the "Adding a theme" chain, add the id to `REMOVED_THEME_REPLACEMENTS` (`lib/templates/theme-ids.ts`) and ship a custom drizzle data migration (`drizzle-kit generate --custom`) remapping `site_data.theme_id` (see `migrations_pg/0011`). Reads go through `resolveThemeId`, so stored old ids render the replacement and `/templates/<old-slug>` 308s to it for free; write paths keep rejecting removed ids.
- **Profile indexability** (`isIndexableProfile` = `!hide_from_search && isIndexableContent`) also needs ≥ 100 words of resume text; it gates the sitemap, `/explore`, `/examples`, JSON-LD and IndexNow, so test fixtures for indexable profiles need realistic content (`INDEXABLE_CONTENT` in `tests/helpers/pglite-db.ts`). The content half is stored as `site_data.content_indexable` (NULL = not computed, treated as not indexable): every write of `site_data.content` must spread `siteDataContentColumns(content)` (`lib/data/site-data-content.ts`), never set `content` alone. List queries (sitemap, `/explore`, `/examples`) filter with `indexableProfileCondition()` (`lib/data/indexable-profiles.ts`) and never select `content`. After a rollback to a Worker older than the flag, run `db:backfill-indexable --since <rollback time>` once the new code is back: old code rewrites content without updating the flag.
- **Template fonts:** load Google Fonts only through `TemplateFontLinks` (CSS `@import`). Cloudflare Fonts is on for the production zone and rewrites any Google Fonts `<link rel="stylesheet">` into inline `<style>` at the edge, which breaks hydration (React #418) — it only shows in production, never in dev or `preview`.
- **Template headings:** `app/globals.css` forces `h1–h4` to `var(--font-display)`, so a template's root font class doesn't reach headings — scope a rule (see `CaseFile.tsx`).
- **Adding a blog post** needs both a `BLOG_POSTS` entry (`lib/blog/posts.ts`) and `app/blog/<slug>/page.tsx` using `getPostBySlug("<slug>")!` at module scope (build throws if they diverge). Titles ≤ 60 chars / descriptions ≤ 160; set `metaTitle` when the H1 is longer.
- **New static route** needs a key in `lib/seo/lastmod.json` and, if public, an entry in `lib/seo/static-pages.ts`.
- **JSON-LD:** always embed via `serializeJsonLd()` (`lib/seo/json-ld.ts`).
- **Toolchain pins:** `vite-plus`, the `vite` catalog alias (`@voidzero-dev/vite-plus-core`), `vitest` and `@vitest/coverage-v8` must stay on the same release, or `--coverage` aborts. The catalog in `pnpm-workspace.yaml` is the single source of truth: the `vite@*`/`vitest@*` overrides and the `@vitest/coverage-v8` override are all `catalog:`, so bumping the catalog entries moves the whole set together (no literal core override is needed — `vite@*: catalog:` already routes vite-plus's pinned alias dep to the one core copy). Dependabot offers them as one `toolchain-minor-patch` group — merge that PR whole, never one package at a time.
- **Dependency freshness:** pnpm's default `minimumReleaseAge` (1440 minutes) applies. `pnpm-workspace.yaml` pins exact-version `minimumReleaseAgeExclude` entries for the versions admitted by the 2026-10-22 one-shot security upgrade, so future releases of those packages stay gated; delete the entries once those versions age in. Dependabot keeps its 1-day `cooldown`.
- **Dependency PRs merge themselves** when green: `.github/workflows/dependabot-automerge.yml` squash-merges grouped/daily minor+patch Dependabot PRs only when `Code Quality`, `Tests`, `Build`, `CI Success`, `GitGuardian Security Checks` and `Workers Builds: clickfolio-me` exist as successful check runs **and** every other observed check/commit status is exactly `success` (literal green — `neutral`/`skipped` refuse). Its own check runs are excluded by workflow-run identity (`actions: read`), not by name; author, base branch, same-repo head and head SHA are re-verified on every poll and right before the merge; branch deletion comes from `delete_branch_on_merge`. Renaming one of those jobs or packages requires updating `EXPECTED_CHECKS`/the patterns in the same commit; majors stay manual (review requested). The workflow is metadata-only (no PR checkout) and only runs from `main`, so it stays inert until it lands. Repo Actions rule 7006 allows `pull_request_target` for that file + `dependabot[bot]` only.
- **`ERR_PNPM_OUTDATED_LOCKFILE`** on a clean checkout after touching `catalog:` deps: run `pnpm install --no-frozen-lockfile` once and commit the lockfile.
- **Browser telemetry ingest** (`/otel/v1/*`) answers 204 and drops data until the `OTEL_BROWSER_INGEST_KEY` secret is put (`wrangler secret put`); the key never ships to the client. Valid bodies are forwarded from `waitUntil` through `externalCall` (`HttpUpstreamFailed`, 10 s); the client always gets 202 and failures only show in the logs.
- **Public-route bodies:** `/api/health` returns fixed strings only (details go to the log). Routes whose body crawlers or caches keep (sitemaps, `/api/og/<handle>`) answer a failed read with `retryLater(...)` (`lib/effect/retry-later.ts`), never a degraded 200. `/api/og/<handle>` inner-joins `site_data` so it matches `/@handle`'s 404.
- **Edge cache (Workers Cache):** every ISR/static page whose render reads no cookies/headers/searchParams is served from the shared cache on `VinextCachedResponse` (`/@handle` 300s, `/examples/*` 3600s, …); `/explore` reads searchParams so it is not edge-cached. A shared render must never depend on the visitor: read the session client-side (like `OwnerDetector`). After a data change call `revalidatePublicProfilePages` (`lib/utils/revalidate.ts`) or `revalidatePath`; it enqueues Cache-Tag digests on `EDGE_PURGE_QUEUE`, and the consumer purges ≤100 tags per batch at ≤5 purges/min (Free-tier limit, per account). Purges only reach the entrypoint that sends them, so purge through `ctx.exports.VinextCachedResponse`, never `ctx.cache` in the default export. Each deploy starts with a cold cache (cache is partitioned by Worker version). The purge consumer settles by the typed failure's `retryable`: timeout/unavailable → `message.retry()` with backoff, rejected/invalid-response → ack plus an `edge purge failed` error log; enqueue failures are logged, never thrown. Failed purges land in `clickfolio-cache-purge-dlq` after 8 retries; logs say `edge purge failed` / `edge purge dead-lettered`. Responses show HIT/MISS in `x-vinext-cache`; browsers always get `private, max-age=0, must-revalidate`.
- **R2 lifecycle:** `deploy.ts` runs `wrangler r2 bucket lifecycle set`, which replaces all rules — keep every rule in `r2-lifecycle.json`.
- **Build fails with `effect must not reach the client bundle`** (`[plugin client-effect-guard]`): each chain starts at the module that imports `effect` and walks up to the client entry. Move the Effect code server-side and give the client an Effect-free module or `import type`. The guard reads the graph before tree-shaking, so a value import from a module that also imports `effect` fails even if the Effect part would be shaken out. Only the build runs it (not `verify` or `dev`).

## Definition of done

1. `pnpm run verify` — lint, format, types, knip (the pre-commit hook runs this too).
2. `pnpm run test` — or the suite(s) covering your change; CI runs integration and security together with `--coverage` and enforces their baseline thresholds.
3. `pnpm run build` when touching config, `worker/`, routes, dependencies, or any module client code imports (the build runs `client-effect-guard`).
4. Schema change → `db:generate` output committed under `migrations_pg/`.
5. This file updated if you changed anything it documents.
